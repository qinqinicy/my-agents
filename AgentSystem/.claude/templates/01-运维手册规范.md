# 软件运维操作手册 - 内容分类与排版规范

> 本规范定义运维手册的内容结构、章节分类及排版格式。
> 生成运维文档时，按本规范的结构和格式输出。

## 二、排版规范

### 2.1 标题层级

```
一级标题：# （文档标题，手册名称）
二级标题：## （章）
三级标题：### （节）
四级标题：#### （小节）
```

**禁止**：
- 避免超过四级标题
- 避免在同级标题下仅有单个子级标题

### 2.2 列表格式

**无序列表**：
- 使用 `-` 或 `*`（统一在一篇文档内）
- 缩进 2 空格

**有序列表**：
- 使用 `1.` `2.` `3.` 格式
- 步骤类列表必须使用有序列表

**列表嵌套**：
- 最多 3 层
- 每层缩进 2 空格

### 2.3 表格格式

```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 内容 | 内容 | 内容 |
```

**表格规范**：
- 表头使用粗体
- 列宽自适应
- 必要时使用表格对齐标记（`:---`、`:--:`、`---:`）

### 2.4 代码块

**行内代码**：
- 使用反引号 `` ` ``
- 示例：`systemctl restart nginx`

**代码块**：
- 标注语言类型
- 示例：
```bash
#!/bin/bash
systemctl restart nginx
```

### 2.5 警告与提示

**注意**：
```markdown
> **注意**：警示性信息
```

**警告**：
```markdown
> **警告**：可能导致数据丢失或服务中断的操作
```

**提示**：
```markdown
> **提示**：有用的补充信息
```

### 4.1 文件命名

```
{system-name}-运维手册-{version}.md
示例：横琴数据中心-运维手册-v1.0.md
```

### 4.2 文档元信息

文档头部应包含：

```markdown
---
title: {系统名称}运维手册
version: {版本号}
date: {编写日期}
author: qin
reviewer: 秦
status: {草稿/已审核/正式发布}
---
```

### 4.3 交叉引用

使用链接引用其他章节：
```markdown
详见 [3.1 巡检操作](#_31-巡检操作)
```

## 五、版本管理

### 5.1 版本号规则

- **主版本号.次版本号.修订号**
- 主版本号：重大架构变更
- 次版本号：新增章节或重大内容调整
- 修订号：小幅修改、错误修正

### 5.2 修订记录格式

```markdown
## 修订记录

|------|------|------|----------|

```

## 六、HTML 转换规则

### 6.1 转换时机

生成运维手册文档后，**自动**将 Markdown 转换为 HTML：
- 输出 `.md` 文件的同时生成 `.html` 文件
- HTML 文件放在同目录下，文件名加 `_out` 后缀或 `html/` 子目录

### 6.2 HTML 输出规范

**文件命名**：
```
{system-name}-运维手册-{version}.md
    ↓
{system-name}-运维手册-{version}.html
```

**HTML 结构要求**：
```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{系统名称}运维手册 v{版本号}</title>
    <style>
        /* 内联样式，保证离线可读 */
    </style>
</head>
<body>
    <!-- 转换后的内容 -->
</body>
</html>
```

### 6.3 样式规范

- 容器最大宽度：1000px，居中
- 整体背景：#fafafa

**代码块样式**：

### 6.4 目录生成

**自动生成目录**：
- 提取所有 h2、h3 标题
- 生成锚点链接
- 放在文档开头或侧边栏

**锚点格式**：
```html
<h2 id="section-1">1. 概述</h2>
<!-- 链接：#section-1 -->
```

### 6.5 转换工具选择

优先使用以下工具（按顺序）：
1. `pandoc` — 最完整的转换
   ```bash
   pandoc {input}.md -o {output}.html --standalone --metadata title="标题"
   ```
2. `markdown-it` / `marked` — 程序化转换
3. 手写 HTML 转换 — 当需要精确控制时

## 七、模板适用范围

**适用场景**：
- 数据库集群运维手册
- 中间件服务运维手册
- 分布式系统运维手册
- 单一服务组件运维手册

**不适用场景**：
- 跨多个子系统的综合运维平台手册
- 包含多个技术栈的混合架构
- 需要变更管理流程的复杂企业IT系统

> 对于通用企业IT系统（包含网络、安全、存储等多层），应使用完整10章结构。
> 对于单一大规模软件（如数据库、消息队列），使用精简6-8章结构更合适。

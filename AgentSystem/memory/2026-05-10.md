## WireGuard VPN 调试完成

### Win1 终于连通

**故障根因**：Win1 配置文件里 PrivateKey 写错了——我把生成的**公钥**当成了**私钥**填进去。

```
错误：PrivateKey = cAxX+dbl7p6MbuUr/3CTx8ysSLbRBahHszmVQkpeJS8=  ← 这是公钥！
正确：PrivateKey = wCGYvD4/pXXWryon8Wx9seDDze8ChIPfvPtr/gUnfUc=  ← 这才是私钥
```

WireGuard 会接受任何 32 字节值作为私钥（Curve25519 clamping），所以不会报错，但会派生出完全不同的公钥（VoGzHuTF... vs 预期的 cAxX+...），导致服务器收到握手但静默丢弃——没有任何错误提示。

**排查过程**：
1. Mac 能通但 Win1 不通 → 问题在 Win1 侧
2. `wg show` 显示 Win1 peer 没有 endpoint/handshake → 握手未到达
3. Win1 `ping 129.204.87.213` 通 → 网络可达
4. 检查 Win1 公钥与服务器不一致 → 发现 key mismatch
5. 更新服务器公钥后仍不通 → 私钥本身无效（错用公钥当私钥）
6. 重新生成正确密钥对 → 通了
7. 抓包确认握手包到达但 WireGuard 静默丢弃 → 确认是密钥问题

**经验教训**：
- WireGuard 配置生成时要严格区分私钥（`wg genkey`）和公钥（`wg pubkey`）
- `wg set` 修改不会持久化到 wg0.conf，重启后丢失
- expect 脚本中 `[]` 会被 Tcl 解释，要用文件上传方式传配置
- 腾讯云 YJ-FIREWALL-INPUT 自定义链默认 DROP，UDP 1194 需手动放行

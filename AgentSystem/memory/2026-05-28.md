## 无人机分段录制服务部署与调试

### 背景
- 无人机每天执行任务，起飞时有视频流
- 需要按 `historyId` 自动分段录制，与现有连续录制并行
- 数据源：MQTT `/ucare/third/uavState` → IoTDB `root.cszl.uav`

### 部署过程
1. **脚本开发**：`drone_segment_recorder.py`
   - MQTT 监听 `/ucare/third/uavState`（broker: 10.129.80.225:1883）
   - `height > 0` + 有效 `historyId` → `[START]` FFmpeg 录制
   - `height == 0` → `[STOP]` 并重命名文件
   - 输出目录：`/opt/media/www/record/cszl/drone/segments/`

2. **systemd 服务**：`drone-segment-recorder.service`
   - 部署到 `/etc/systemd/system/`
   - `Restart=always`

3. **运维手册更新**：视频平台运维手册 v2.4
   - 新增 5.5 章节「无人机分段录制配置」

### 踩坑记录

#### Bug 1: threading.Lock 死锁
- **现象**：任务结束不发 height=0，录制一直挂着；signal 退出时文件大小为 0
- **根因**：`on_message` 持锁后调用 `stop_recording`，`stop_recording` 内部又抢同一把 `threading.Lock`，死锁
- **修复**：`threading.Lock` → `threading.RLock`（可重入锁）

#### Bug 2: MQTT 静默导致录制不停止
- **现象**：任务结束后 MQTT 不再发消息，脚本永远等不到 height=0
- **根因**：无人机任务结束时 MQTT 流直接断掉，不会发 height=0
- **修复**：增加 `MQTT_SILENCE_TIMEOUT = 300`（5 分钟），录制中 MQTT 静默超 5 分钟自动 `[STOP]`

#### 配置修正
- 初始误配为 `/ucare/third/uavParam`，实际应为 `/ucare/third/uavState`
- 初始误配 broker 为 10.129.80.142（IoTDB 侧），实际应为 10.129.80.225（MQTT 源侧）

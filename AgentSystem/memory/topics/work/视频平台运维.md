## rclone sync 脚本

**位置**: `/opt/media/tools/sync_by_scene.sh`

```bash
#!/bin/bash
set -e
LOG="/opt/media/logs/sync.log"
SRC_DIR="/opt/media/www/record"

RCLONE="/opt/media/tools/rclone"

for scene_dir in "$SRC_DIR"/*/; do
    scene=$(basename "$scene_dir")
    # 跳过非场景目录
    [[ "$scene" == "live" ]] || [[ "$scene" == "proxy_example" ]] && continue
    # 桶不存在则跳过
    $RCLONE lsd minio: | grep -q "${scene}-media" || continue
    $RCLONE sync "$scene_dir" "minio:${scene}-media/" \
        --exclude "**/.*" --transfers 4 --checkers 8 --log-level INFO -P
done
```

**Crontab**: `*/5 * * * * /opt/media/tools/sync_by_scene.sh >> /opt/media/logs/sync.log 2>&1`

## 无人机分段录制服务（2026-05-27 新增）

### 功能
- 与现有 ZLM 连续录制并行运行
- 按 `historyId` 自动分段：起飞（height>0）开始录制，降落（height=0 或 MQTT 静默 5 分钟）停止并保存

### 部署文件

| 文件 | 服务器路径 | 说明 |

| `drone-segment-recorder.service` | `/etc/systemd/system/drone-segment-recorder.service` | systemd 配置 |

### 配置参数


### 踩坑记录

1. **threading.Lock 死锁** (2026-05-27)
   - 现象：任务结束不发 height=0，录制一直挂着；signal 退出时文件大小为 0
   - 根因：`on_message` 持锁后调用 `stop_recording`，内部又抢同一把 `threading.Lock`，死锁
   - 修复：`threading.Lock` → `threading.RLock`（可重入锁）

2. **MQTT 静默导致录制不停止** (2026-05-27)
   - 现象：任务结束后 MQTT 不再发消息，脚本永远等不到 height=0
   - 根因：无人机任务结束时 MQTT 流直接断掉，不会发 height=0
   - 修复：增加 `MQTT_SILENCE_TIMEOUT = 300`，录制中 MQTT 静默超 5 分钟自动 `[STOP]`

3. **topic 误配** (2026-05-27)
   - 初始误配为 `/ucare/third/uavParam`，实际应为 `/ucare/third/uavState`

4. **socat systemd 路径错误** (2026-05-28)
   - 现象：`socat-rtmp-proxy.service` 启动失败 `status=203/EXEC`
   - 根因：`ExecStart=/usr/local/bin/socat`，实际二进制在 `/usr/bin/socat`
   - 修复：`sed -i 's|/usr/local/bin/socat|/usr/bin/socat|'` + `daemon-reload` + `restart`

5. **threading.Lock 死锁复发** (2026-05-28)
   - 现象：服务启动后只打印 `[START]`，后续无任何日志，FFmpeg 进程消失
   - 根因：`silence_watchdog` 持 `threading.Lock` 调用 `stop_recording`，`stop_recording` 内部再抢同一把锁 → 死锁
   - 修复：`threading.Lock` → `threading.RLock`（可重入锁），已在生产环境验证

6. **脚本升级：按日期分目录 + 同 historyId 合并** (2026-05-28)
   - 按日期分目录：`segments/2026-05-28/` 子目录存储
   - 同 historyId 自动合并：每次 `[STOP]` 后调用 `ffmpeg -f concat` 合并当天同一 historyId 的所有片段
   - `HISTORY_SILENCE_TIMEOUT` 从 300s 调整为 30s

7. **StreamUI 播放页显示"无录像"** (2026-05-29)
   - 现象：StreamUI 列表能扫描到 `drone-segment` 流（61 segments, 6.17GB），但播放页显示"无录像"
   - 根因：FFmpeg 录制的 MP4 缺少 `creation_time` 元数据，StreamUI 过滤掉无效 creation_time 的文件
   - 修复：停止录制后增加 `faststart_remux()` 并注入 `creation_time`，格式为 UTC 时间（`datetime.utcfromtimestamp()`）

8. **faststart 输出到同目录 `.tmp` 触发 FFmpeg exit 234** (2026-05-29)
   - 现象：`faststart_remux()` 输出到同目录 `.tmp` 时 FFmpeg 报 exit 234，但输出到 `/tmp` 成功
   - 根因：未知（可能与文件系统或 FFmpeg 7.0.2 的临时文件处理有关）
   - 修复：`faststart_remux()` 输出路径改为 `/tmp/faststart_{uuid}.mp4`，成功后 `os.replace()` 移回原位

9. **creation_time 时区偏移** (2026-05-29)
   - 现象：StreamUI 时间轴显示比实际时间多 8 小时（如 10:32 显示为 18:32）
   - 根因：注入的 `creation_time` 使用北京时间但带 `Z`（UTC）后缀，StreamUI 按 UTC 解析后再转本地时区
   - 修复：`creation_time` 必须用 UTC 时间 = 北京时间 - 8 小时，使用 `datetime.utcfromtimestamp()` 生成

## 经验教训

- ZLM Docker 必须使用 `--network host` 否则跨网络通信失败
- addStreamProxy 必须传 `vhost=__defaultVhost__`
- ZLM addStreamProxy 对某些 RTMP URL 格式无法拉取（报错 "rtmp url非法" 或 "end of file"），此时用 ffmpeg 中转
- rclone serve 默认绑定 IPv6，需加 `--bind 0.0.0.0` 绑定 IPv4
- rclone sync 正在录制的文件会报 "sizes differ"，需排除 `.` 开头的临时文件 `--exclude "**/.*"`
- MinIO IAM 可实现按场景桶级别的细粒度权限控制
- **threading.Lock 死锁**：MQTT 回调中若调用同锁函数，必须用 `threading.RLock`
- **MQTT 静默兜底**：IoT 设备任务结束时可能不发送"结束"消息，需加超时机制自动关闭资源
- **FFmpeg 录制优雅退出**：`terminate()` + `wait(timeout=8)`，超时才 `kill()`，否则 MP4 文件头不完整

## WireGuard VPN（2026-05-08/09）

### 腾讯云服务器 WireGuard 部署
- 私钥：`2K4q+GOLkYZgAPVqxqxmg4e74Pi+cF3Fb933XEkDVn8=`
- 公钥：`+ZbN9CSiLmEyahRPDo46SXEIx5LXaRNGJqhrlEPol1Q=`
- 监听：1194/UDP，VPN 网段：10.0.0.0/24

### 腾讯云防火墙（YJ-FIREWALL-INPUT）
- 默认 policy DROP，大量 IP 黑名单
- 放行 WireGuard：`iptables -I YJ-FIREWALL-INPUT 1 -p udp --dport 1194 -j ACCEPT`
- 需添加 MASQUERADE：`iptables -t nat -A POSTROUTING -s 10.0.0.0/24 -o eth0 -j MASQUERADE`

### 故障排查（已解决 2026-05-10）

| 问题 | 原因 | 解决 |
|------|------|------|
| Mac ping 不通 10.0.0.1 | peer 未持久化到 wg0.conf，重启后丢失 | 写入 wg0.conf + `wg-quick down/up` |
| Mac 握手成功但 ping 不通 | YJ-FIREWALL-INPUT 只放行了 UDP 1194，MASQUERADE 未生效 | PostUp 脚本 + 手动添加 NAT 规则 |
| Win1 握手到达服务器但不回复 | PrivateKey 错填为公钥，派生出错误密钥对 | 重新生成正确密钥对，服务器更新公钥 |

### 经验教训

- **WireGuard 配置生成**：`wg genkey` 产私钥，`wg pubkey < priv` 产公钥，严禁混用
- **`wg set` 不持久化**：重启 `wg-quick` 后会丢失，必须写入 wg0.conf
- **握手静默丢弃**：公钥不匹配时 WireGuard 不报错，只是不理，需抓包 + `wg show` 联合排查
- **expect 避坑**：`[]` 被 Tcl 解释，传 WireGuard 配置用 SCP 文件上传
- **腾讯云防火墙**：YJ-FIREWALL-INPUT 链优先级高，INPUT 默认 DROP

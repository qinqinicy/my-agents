3.2.4 Oryx start_redis 修复

问题：Oryx 容器内 auto/start_redis 被 bootstrap 调用，不能用 exec bootstrap 替换进程，否则导致递归循环。

解决方案：修改 /tmp/start_redis 挂载为容器，覆盖默认的 start_redis：

cat > /tmp/start_redis << 'EOF'
#!/usr/bin/env bash
WORK_DIR=/usr/local/oryx/platform
# Load environment variables from .env
if [[ -f ${WORK_DIR}/containers/data/config/.env ]]; then
    export $(grep -v '^#' ${WORK_DIR}/containers/data/config/.env | xargs)
fi
echo "Using external Redis at 127.0.0.1:6379, skip internal Redis start"
# Just return - bootstrap will continue to start SRS after this
EOF
chmod +x /tmp/start_redis

# 重新运行 Oryx（挂载修复后的 start_redis）
docker stop oryx
docker rm oryx
docker run -d --name oryx \
  --network host \
  -v /tmp/start_redis:/usr/local/oryx/platform/auto/start_redis \
  -v /opt/media/oryx/redisconf/redis.conf:/usr/local/oryx/platform/containers/conf/redis.conf \
  -e SRS_API_PORT=1985 -e SRS_RTMP_PORT=1935 -e SRS_API_SECRET=mysecret123 -e SRS_SERVER_PORT=1935 \
  registry.cn-hangzhou.aliyuncs.com/ossrs/oryx:5

5. 接入配置

5.1 SRS ingest 拉流配置

核心功能：SRS ingest 内置自动拉取外部 RTMP/HTTP-FLV 流，无需手动调用 API。

功能：通过 SRS 配置文件中的 ingest 块，自动 fork ffmpeg 拉取外部流并推送到本地。

前置条件：

  • SRS 服务运行中
  • 外部流来源可达
  • ffmpeg 路径正确（/usr/local/srs/objs/ffmpeg/bin/ffmpeg）

操作步骤：

  1. 编辑 /opt/media/srs/conf/docker.conf
  2. 添加或修改 ingest 块
  3. 重启 SRS 容器

验证方法：

  • curl -s "http://127.0.0.1:1985/api/v1/streams" 显示活跃流
  • 录像目录出现新文件

ingest 配置示例

# RTMP 源拉流
ingest livestream {
    enabled on;
    input {
        type stream;
        url rtmp://10.129.80.244:1935/proxy_example;
    }
    ffmpeg /usr/local/srs/objs/ffmpeg/bin/ffmpeg;
    engine {
        enabled on;
        output rtmp://127.0.0.1:1935/live/proxy_example;
    }
}

# HTTP-FLV 源拉流
ingest uavstream {
    enabled on;
    input {
        type stream;
        url http://10.129.80.244:21021/apron/UA004768282.flv;
    }
    ffmpeg /usr/local/srs/objs/ffmpeg/bin/ffmpeg;
    engine {
        enabled on;
        output rtmp://127.0.0.1:1935/live/UA004768282;
    }
}

5.3 录像同步配置

功能：配置 rclone 将本地录像同步到 MinIO 存储

前置条件：

  • rclone 已安装并配置
  • MinIO 服务正常

操作步骤：

  1. 创建同步脚本
  2. 配置定时任务
  3. 验证同步结果

验证方法：

  • mc ls minio/cszl-media/cszl/ 显示同步的文件
  • 同步日志无错误

sync_to_minio.sh 脚本

#!/bin/bash
# 录像同步到 MinIO 脚本
# 位置：/opt/media/tools/sync_to_minio.sh

SRC="/opt/media/srs/objs/nginx/html/record"
LOG="/opt/media/logs/sync.log"
DATE=$(date '+%Y-%m-%d %H:%M:%S')

log() {
    echo "[$DATE] $1" | tee -a "$LOG"
}

log "=== 开始同步录像到 MinIO ==="

/opt/media/tools/rclone sync "$SRC" minio:cszl-media/cszl/ \
    --exclude "**/.*" \
    --transfers 4 \
    --checkers 8 \
    --log-level INFO \
    -P 2>&1 | tee -a "$LOG"

RESULT=$?
if [ $RESULT -eq 0 ]; then
    log "同步成功完成"
else
    log "同步失败，退出码: $RESULT"
fi

log "=== 同步任务结束 ==="
echo "" >> "$LOG"

定时任务配置

# 添加到 crontab，每 5 分钟执行一次
crontab -e

# 内容：
*/5 * * * * /opt/media/tools/sync_to_minio.sh >> /opt/media/logs/cron_sync.log 2>&1

手动执行

# 手动执行同步（实时显示进度）
/opt/media/tools/rclone sync /opt/media/srs/objs/nginx/html/record/ minio:cszl-media/cszl/ --exclude "**/.*" -P

8. 故障排除

8.1 常见问题汇总

Q1: SRS ingest 拉流失败

问题现象：SRS 日志无 ingest 相关输出，外部流未拉取

可能原因：

  • 源流地址不可达
  • ffmpeg 路径不正确
  • ingest 配置语法错误

处理步骤：

  1. 检查源流是否可达：ffmpeg -i rtmp://10.129.80.244:1935/proxy_example
  2. 检查 ffmpeg 路径：docker exec srs ls -la /usr/local/srs/objs/ffmpeg/bin/ffmpeg
  3. 检查 SRS 日志：docker logs srs --tail 100 | grep -i ingest
  4. 验证配置语法，重启 SRS

Q2: Oryx 8080 端口绑定失败（errno=98）

问题现象：Oryx 容器启动失败，日志显示 Bind socket failed at 0.0.0.0:8080

可能原因：

  • 端口已被占用（但 ss 显示无占用，可能与容器网络模式有关）
  • SRS 残留进程占用端口

处理步骤：

  1. 检查是否有进程占用：ss -tlnp | grep 8080
  2. 检查 SRS 是否残留：ps aux | grep srs
  3. 重启服务器后重新启动 Oryx
  4. 如问题持续，尝试不绑定 Oryx（使用 SRS 原生 Web 控制台）

Q3: Oryx start_redis 循环递归

问题现象：容器内出现大量 bash /usr/local/oryx/platform/bootstrap 进程

可能原因：

  • start_redis 脚本中使用了 exec /usr/local/oryx/platform/bootstrap
  • 导致 bootstrap 被替换后又重新调用 start_redis，形成无限递归

处理步骤：

  1. 停止并删除 Oryx 容器
  2. 修复 start_redis 脚本（不能使用 exec，直接返回）
  3. 重新创建容器并挂载修复后的脚本

Q4: 录像不同步到 MinIO

问题现象：MinIO 中没有新录像文件

可能原因：

  • rclone 服务未运行
  • 同步脚本执行失败
  • 正在录制的文件（以 . 开头）被排除

处理步骤：

  1. 检查 rclone 服务：systemctl status rclone-minio
  2. 检查同步日志：tail /opt/media/logs/sync.log
  3. 手动执行同步测试：/opt/media/tools/sync_to_minio.sh

Q5: 第三方无法访问视频

问题现象：访问 http://IP:8091 返回连接失败

可能原因：

  • rclone 未绑定 IPv4
  • 防火墙未开放端口

处理步骤：

  1. 检查监听地址：ss -tlnp | grep 8091
  2. 如显示 [::]:8091，需要添加 --bind 0.0.0.0
  3. 修改 systemd 服务并重启

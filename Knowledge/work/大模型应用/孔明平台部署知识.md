## 二、架构模式

### 模式 A：一体化部署（推荐有 GPU 环境）

```
单台 GPU 服务器
├── 孔明平台（Docker 容器）
├── Alita 推理服务（Docker 容器）
└── 基础模型（本地部署）
```

**硬件要求**：
- CPU: 32 核
- GPU: 24G 显存×4（A100 级别）
- 内存：64G
- 存储：1TB

---

### 模式 B：分离部署（无 GPU 环境）

```
┌─────────────────┐     ┌─────────────────┐
│  虚拟机         │     │  物理机         │
│  孔明平台       │ ←→  │  Ollama 服务    │
│  (无 GPU)       │     │  (有 GPU)       │
└─────────────────┘     └─────────────────┘
```

**适用场景**：
- 虚拟机无 GPU 直通
- 物理机已有大模型服务（如 Ollama）
- POC 测试/开发环境

## 三、核心配置项

### 3.1 孔明平台配置文件（~/ai/.env）

```bash
# Web 服务
WEB_PORT=8081                    # Web 访问端口

# 模型服务
ALITA_HOST=192.168.2.65          # Alita 服务 IP（或 Ollama IP）
OLLAMA_API_HOST=http://192.168.2.65:11434
DEFAULT_LLM_MODEL=qwen3:8b

# 监控
OTEL_COL_HOST=192.168.2.100      # 虚拟机 IP
```

### 3.2 Ollama 配置（物理机）

```bash
# 环境变量（允许外部访问）
OLLAMA_HOST=0.0.0.0:11434

# 防火墙规则
New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound -Protocol TCP -LocalPort 11434 -Action Allow
```

### 3.3 Rerank 服务（Python 部署）

```python
# 依赖
FlagEmbedding
fastapi
uvicorn
pydantic

# 服务端口
PORT=8900
```

## 五、故障排查流程

```
1. 服务无法访问
   ├─→ 检查容器状态：docker ps
   ├─→ 查看容器日志：docker logs <容器名> --tail 100
   └─→ 重启服务：ai restart

2. Ollama 无法连接
   ├─→ 检查 Ollama 服务：ollama list
   ├─→ 检查环境变量：OLLAMA_HOST
   ├─→ 检查防火墙：防火墙规则
   └─→ 测试连通性：curl http://IP:11434/api/tags

3. Rerank 服务不可用
   ├─→ 检查 Python 进程：ps aux | grep rerank
   ├─→ 检查端口监听：netstat -tlnp | grep 8900
   └─→ 查看日志：/tmp/rerank.log

4. 容器持续重启
   ├─→ 查看依赖服务：docker ps | grep -E mysql|redis
   ├─→ 查看应用日志：docker logs <容器名>
   └─→ 等待依赖服务启动后重试
```

## 六、经验教训

### ✅ 正确做法

1. **网络配置**：虚拟机使用桥接模式，确保与物理机同网段
2. **服务分离**：无 GPU 环境将模型服务部署在物理机
3. **端口管理**：避免端口冲突（8080→8081）
4. **防火墙**：提前开放所需端口

### ❌ 错误做法

1. ~~在虚拟机强求 Alita 服务（无 GPU 环境）~~
2. ~~Ollama 不配置 OLLAMA_HOST 环境变量~~
3 ~~忽略防火墙规则导致端口不通~~
3. ~~容器重启时不查看日志直接重启~~
